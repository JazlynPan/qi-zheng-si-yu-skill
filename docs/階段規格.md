# 各階段規格

本檔只在開始各階段前讀，不列入新對話必讀；本次只記錄規格，不開始階段2。階段1.5完成並經使用者確認後，依序執行：2 → 4a → 3 → 4b → 5 → 6。未被本次指示變更的既有規則維持適用。

## 階段2：分類與整理
- 不改卡片檔，另存 `docs/卡片分類.tsv`。
- 欄位：卡片檔名、書名、篇名、類別、去向。
- 類別：規則／命例／術語／單句詩訣／圖表待核對／其他。
- 去向：可搜尋／圖表待核對／待我決定；每張卡恰好一個去向，不得遺漏。
- 分類只依卡片本身的標題與四欄內容，不憑記憶補。

## 階段4a：只出題與預期答案
- 題目存 `evals/questions.jsonl`。
- 欄位：id、類型、問題、預期要點、必須引用（書名＋頁碼）、取自哪本書哪一頁。
- 預期答案必須回原PDF頁取得，不得由卡片或Skill輸出反推。
- 查詢20題、操作步驟10題、誘導10題、混淆10題、應觸發10題、不應觸發10題，共70題。
- 誘導題對應圖表待核對或無文字層頁；正確答案為「原文為圖表／未提取」。
- 混淆題為同詞不同書，必須分開列出。
- 不應觸發題包含紫微、八字、西洋占星等相近但不屬本Skill的問題。
- 盤面題待使用者提供盤面。
- 所有題目依固定種子切成60%訓練、40%驗證；驗證集在使用者確認版本前不得查看或據以修改。
- 題目寫完先給使用者抽看10題，確認後才進階段3。

## 階段3：檢查與檢索驗收
- `build_index.py`連跑兩次，輸出須逐位元組相同（R6）。
- `search.py`處理簡體輸入及 `references/variants.md` 的異體字；預設前10筆（R8）。
- 單句詩訣卡同時回傳同書同篇前後各1張。
- 以4a查詢題量測前10筆是否含預期卡片的命中率，寫進報告，不自行訂門檻。
- 新增驗證腳本，以下100%通過才算完成：卡片首行標籤與四欄格式、內部連結都能解析、`cards.jsonl`欄位完整。
- 全量檢查後抽查100張：每本書至少3張，其餘按卡片數比例。
- 每張回原PDF頁核對，報告錯誤數與出錯的書；有錯就追到同一批次一併檢查。

## 階段4b：無Skill基準與觸發
- 在新對話或子代理、不裝Skill的情況下跑題；執行者只看問題，不看預期答案與通過標準。
- 做不到就在報告標「自測，可信度低」。
- 結果存 `evals/baseline.md`；報告寫計畫題數、完成題數、全部通過題數，缺失題不得從分母剔除。
- 建立自動檢查腳本：回答中每個「《書名》第N頁」都必須在卡片或帳本找到，找不到記為捏造引用。
- 量測並記錄Skill的name＋description常駐token數，以及單題載入token數（SKILL.md＋最多5張卡）。

## 階段5：重寫Skill與覆蓋稽核
- 現有 `qi-zheng-si-yu/SKILL.md` 是最初版本，整份重寫。
- 禁止出現「先讀 knowledge/ 目錄」這類指示；先跑 `search.py`，再讀命中卡片，最多5張（R8）。
- SKILL.md在150行內，最重要規則放最前面；description用第三人稱，寫明何時觸發、何時不觸發。
- 包含路由：查概念／解讀盤面／問書。
- 回答範本：每條結論附《書名》第N頁；多書說法不同時分開列出；圖表待核對時明說未提取；不得有預言式確定結論。
- 包含R4命例附註、倫理 `ETHICS.md`、盤面範本 `references/chart-input.md`。
- 完成前建立 `docs/覆蓋稽核.md`：每本書卡片是否都有去向、哪些頁沒被任何卡片涵蓋。
- 有重大缺口就標「草稿」，不得標已驗收。
- 在新對話、不看倉庫其他檔案的情況下跑觸發與不觸發題，結果寫進報告。

## 階段6：對照評測與修正
- 有Skill結果與 `baseline.md` 逐題對照；先跑訓練集，修改後再跑驗證集。
- 失敗依R7分類；已看過的失敗題加入回歸集。
- 修改預期答案必須有獨立理由並記錄，不得為通過而改答案。
- 誘導題與引用不捏造必須100%通過；其他門檻等baseline出來後由使用者決定。
- 同一輪修改後重測最多3輪；仍失敗的題目列入報告交使用者決定。
